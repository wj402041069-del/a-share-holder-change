# A股股东增减持家数 · 每日趋势

用**重要股东增减持公告**衡量 A 股的「披露口径股东行为宽度」：每天多少家公司的股东在增持、多少家在减持，以及 20 交易日的净家数趋势。

## 一、看什么

1. **净家数趋势（主图）**：`净家数 = 增持公司家数 − 减持公司家数`，主图是 **20 交易日累计净家数**（红正绿负）。可切近 3 月 / 1 年 / 3 年 / 全部。
2. **每日增减持家数（副图）**：最近 120 个交易日，红色向上是增持家数，绿色向下是减持家数。
3. **四个读数**：当日净家数、20 日累计净家数、20 日增持占比、该占比在近 5 年的历史分位。
4. **沪深300 同轴对照**：主图左轴是 20 日净家数，右轴可叠加沪深300点位（橙，默认开）和沪深300分位（紫，默认关）；鼠标在图上移动，tooltip 同时给出日期、增减持家数、净家数分位、沪深300点位/分位、分位差。切换时间范围时三者始终同轴对齐。
5. **最近 10 日表**：逐日明细（含净家数分位、沪深300、分位差），最近两天标「未定稿」。

> 已按用户要求**移除日度增减持柱图**。现在四个维度齐全：**广度（家数）、力度（金额）、已发生（增减持）、将发生（解禁）**。

6. **金额口径切换**：主图 toolbar 点「切换金额口径」，左轴从「净家数」变为「净金额（亿元）」，同一套时间轴和跨境对照；金额按 `CHANGE_NUM(万股) × CLOSE_PRICE ÷ 10000` 估算，3% 缺价记录按 0 计，只看相对趋势。
7. **未来 30 天解禁**：单独卡片区，显示解禁总市值 / 笔数 / 单日峰值 + 每日柱状图。解禁 ≠ 减持，只是「可卖筹码变多」的日历事件，与实际减持并列看。

## 二、口径（改动前必读）

| 项 | 取值 | 为什么 |
| :--- | :--- | :--- |
| 数据源 | 东财 `RPT_SHARE_HOLDER_INCREASE`（重要股东增减持公告） | 董监高接口 `RPT_EXECUTIVE_HOLD_DETAILS` 同日只有个位数记录，太稀疏，不适合做宽度 |
| 日期轴 | **`NOTICE_DATE` 公告日** | `END_DATE` 是交易截止日，一条公告横跨数月，按它归集会反复改写历史 |
| 计数单位 | **按 `SECURITY_CODE` 去重的公司家数** | 一条记录是一个股东的一次变动；数记录条数或股东人次都会放大同公司的权重 |
| 方向判定 | 只用 `DIRECTION`（`增持` / `减持`） | 数据源存在「减持但 `CHANGE_NUM` 为正」的记录，符号必须看 `CHANGE_NUM_SYMBOL` 或直接用方向字段 |
| 主窗口 | 20 交易日 | 单日只有十来家公告，噪声太大；20 日累计才看得出趋势 |
| 历史长度 | 5 年 | 与市场宽度面板对齐 |

### ⚠️ 50% 不是中性线（本面板最重要的一条）

这套披露口径**天然减持远多于增持**：实测 5 年日均 **增 3.4 家 / 减 14.9 家**，20 日增持占比的历史中位只有 **17.4%**（区间 0%~72.7%）。

原因是披露规则不对称——大股东减持属于法定强制披露，增持多为自愿披露。**所以不要把 50% 当作荣枯线**。卡片里的「历史中位」是本序列自己的基准，判断冷热请优先看「历史分位」。

> 2026-11-19 实测：20 日增持占比 49.5%，看似低于 50%，实则处于近 5 年 **97.5 分位**（极其少见的高值）。这正是「用 50% 会读反」的典型例子。

## 三、数据链路

```
东财 datacenter-web /api/data/v1/get
  reportName=RPT_SHARE_HOLDER_INCREASE
  filter=(NOTICE_DATE>='...')(NOTICE_DATE<='...')
        │  build.py（每天回看 12 个自然日，捞迟到公告）
        ▼
  history.json   ← 逐日家数，随仓库提交，唯一主数据资产
        │  derive()：20 日滚动累计 + 250 日滚动分位
        ├──────────────┐
        ▼              ▼
  hs300.json      docs/index.html  ← 单文件零外链，数据内嵌
  腾讯日K               │  Actions 提交回 main
  (独立宿主)            ▼
                  GitHub Pages
```

**沪深300 对照的口径**：

- 数据：腾讯 `web.ifzq.gtimg.cn` 的 `sh000300` 前复权日K，约 1,200 根 / 5 年，每天随日报一起抓；抓不到就沿用本地 `hs300.json` 缓存，页面照常发布。
- 分位：**净家数20日累计**和**沪深300收盘价**各自算 250 交易日滚动 percentile rank（0–100）。不对净家数做「归一到 100」——它有负值、均值为负，min-max 映射会失真。
- 分位差 = 净家数分位 − 沪深300分位（−100~+100），只作**描述性背离读数**。
- **非交易日的点位处理**：公告日包含周六（5 年 239 个）及少量节假日（18 个），这些日子沪深300没有行情。生成时对 `px` / `hp` 做 **carry-forward**——沿用最近一个更早交易日的收盘与分位（非交易日指数点位本来就不变，是标准做法，不是编造数据）。这样点位线连续不中断；tooltip 会标注「非交易日沿用前收盘」，并且 `px_cf` 字段记录该行是否被填充。**净家数本身不做任何填充**——那几天是真实有公告的。
- **实测相关性很弱**：5 年 1,171 个共同交易日，20 日净家数与沪深300未来 20 日收益的相关系数在 −0.12 ~ +0.10 之间。所以**不设「可买 / 禁买」分档**，页面明确标注「非买卖信号」。

> 2026-11-19 实例：净家数分位 100.0、沪深300分位 1.6、分位差 +98.4——极端背离，但只能当背景，不能当交易指令。

- 首次建仓用 `python build.py --backfill` 回填 5 年（约 4.7 万条公告、93 页串行）；日常只需要 `python build.py`。
- 单日增量约 20~30 条，1 页搞定。
- **当日 17:00–19:00 公告才陆续入库**，所以最近 1~2 日在页面和表格里标「未定稿」，隔日回看才稳定。
- 工作流：北京时间 **21:20**（UTC 13:20），周一至周五，可手动触发。

## 四、降级与护栏

- 东财返回空表 / `success=false` / 0 条记录 → **按失败处理，不写 history.json、不覆盖页面**（不重演「200 + 空数组被当成没数据」的事故）。
- 校验脚本 `check.py` 任一项不过就非 0 退出，旧产物继续有效；`asof` 距今超过 7 天直接拒绝发布。
- 页面数据内嵌、零外链，不依赖任何运行时 API，也不消耗 Worker 配额。
- 本面板不需要 `A_STOCK_API_KEY`——它直连东财，不经过共享 Worker。
- **页面过期警示**：浏览器加载时按「工作日」对比 `asof` 与当天，连续缺 4 个工作日以上就在标题挂红色「⚠ 数据已过期 N 个工作日」标签。周五数据到周一不会误报。
- **备用源只做诊断，不替换数值**：`build.py` 在主源返回 0 条时会探一次巨潮资讯（`cninfo.com.cn` 公告检索）。若巨潮同期有增减持公告，报错里会明确写「疑似主源缺数」；巨潮不可用则静默跳过。两套口径不同（东财是结构化变动记录、巨潮是标题含增减持的公告，实测同日 7 增/4 减 vs 14 增/3 减），**绝不能把巨潮的数字混进同一张趋势图**。
